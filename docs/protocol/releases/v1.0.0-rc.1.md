# Mind Protocol 1.0.0-rc.1

Mind Protocol `1.0.0-rc.1` is the final-contract release candidate built from the public `0.9.0` compatibility freeze.

It is a **GitHub prerelease**, not yet the `1.x` compatibility guarantee. That guarantee begins only with stable `1.0.0`.

## Exact delta from 0.9.0

The protocol semantic delta remains deliberately narrow:

- protocol version advances from `0.9.0` to `1.0.0-rc.1`;
- compatibility lifecycle advances from `frozen_pre_1_0` to `release_candidate`;
- conformance support range becomes `>=1.0.0-rc.1 <1.0.0`;
- supported stable migration sources include formal `0.9.0` alongside `0.6.0`, `0.7.0`, and `0.8.0`;
- supported-range evaluation uses strict SemVer 2.0 prerelease precedence;
- illegal numeric prerelease identifiers with leading zeroes are rejected;
- build metadata does not alter precedence.

No published JSON Schema shape changes in this candidate. The frozen `0.9.0` schema `$id` values and Git blob fingerprints remain unchanged.

## Repository authority split

Before RC publication, protocol authority was physically separated from the historical concrete `mind@0x0sky` repository.

- historical first release `v0.9.0` remains immutable in `0x0sky/mind`;
- exact protocol Git ancestry through commit `48a81df7d8e9818d9c01f3e1fe5ac663af29a006` is preserved in `aiaiaiai-org/mind-protocol`;
- `aiaiaiai-org/mind-protocol` now contains protocol authority only and has no root concrete `manifest.yaml`;
- `0x0sky/mind` is now only a concrete consumer;
- concrete Minds are created from exact releases via deterministic neutral bootstrap, not from copied implementations.

This physical split is repository/release machinery, not a new universal protocol concept. `mind-repository.yaml` remains repository metadata and is not promoted into the protocol contract.

See [`../../REPOSITORY_MODEL.md`](../../REPOSITORY_MODEL.md), [`../AUTHORITY_MIGRATION.md`](../AUTHORITY_MIGRATION.md), and [`../BOOTSTRAP.md`](../BOOTSTRAP.md).

## Bootstrap boundary

Canonical creation is:

```text
exact immutable protocol release
→ neutral baseline
→ explicit subject + publication owner + Identity
→ concrete mind@<id>
→ authored modules/resources only
```

Bootstrap records `aiaiaiai-org/mind-protocol` as source authority, requires the exact checked-out release tag, rejects dirty released contracts, and copies no authored content from another concrete Mind.

## Conformance

Both required consumer modes continue to exercise synthetic `person`, `organization`, `agent`, `project`, and `product` subjects. The RC proves:

- `1.0.0-rc.1 < 1.0.0`;
- `1.0.0-rc.2 > 1.0.0-rc.1`;
- build metadata does not alter precedence;
- invalid numeric prerelease identifiers are rejected;
- concrete bootstrap output is schema-valid, Identity-bound, and exact-release locked;
- protocol-repository CI contains no named concrete-Mind dependency.

Existing provenance, canonical visual resolution/failure, optional/required module, frozen root-manifest, neutral baseline, and dual-consumer probes remain required.

## Migration from 0.9.0

A conforming `0.9.0` Mind needs no manifest-shape migration. A concrete consumer should, after RC publication:

1. consume exact `v1.0.0-rc.1` from `aiaiaiai-org/mind-protocol`;
2. update its protocol binding to `1.0.0-rc.1`;
3. keep canonical subject, owner, Identity, authored provenance, and provider-independent IDs;
4. keep `mind.context_version` unchanged unless durable authored context changed;
5. rerun its normal contract validation against the exact RC set.

Historical `0.9.0` provenance is not rewritten merely because canonical authority moved before the RC.

## Known limitations

- the RC carries no stable `1.x` compatibility promise;
- full named visual-family/provider/agent/project/product rollout remains post-`1.0.0` work;
- a blocking universal defect requires a later RC, never mutation of `rc.1`;
- concrete implementation defects remain owned by the affected consumer unless they expose a universal protocol defect.

## Publication boundary

This source file does not publish the candidate. Formal publication is a separate manual `Publish Mind Protocol Release` action using `prerelease` from the verified post-split `master` merge commit whose tree equals the green PR-head tree.

The immutable publication target, if approved, is `v1.0.0-rc.1`.
