# Mind Protocol 1.0.0-rc.2

Mind Protocol `1.0.0-rc.2` is the second and intended final release candidate before the first compatibility-guaranteed stable `1.0.0` release.

It exists because `1.0.0-rc.1` proved the frozen protocol contracts and four real consumers, but the canonical concrete-Mind bootstrap still recorded release provenance in an older metadata shape. That tooling defect was corrected after `rc.1` publication and must be exercised as an immutable prerelease before stable promotion.

`rc.1` remains immutable and valid historical evidence. `rc.2` does not rewrite it.

## Exact delta from rc.1

The universal protocol semantics remain unchanged. This candidate deliberately changes only release identity and canonical bootstrap/repository provenance behavior:

- protocol version advances from `1.0.0-rc.1` to `1.0.0-rc.2`;
- `protocol.yaml`, `conformance.yaml`, and `compatibility.yaml` bind to the new exact candidate version;
- the RC support range remains `>=1.0.0-rc.1 <1.0.0`, because no compatibility-breaking protocol semantic change was introduced;
- concrete bootstrap records the exact `aiaiaiai-org/mind-protocol` release repository, tag, and 40-character release commit consistently in both `mind-repository.yaml` and `protocol.lock.yaml`;
- bootstrap rejects a checkout whose `HEAD` is not the exact requested release-tag commit;
- generated concrete-Mind metadata is deterministic for identical inputs.

No published JSON Schema bytes or `$id` values change in `rc.2`. The frozen schema fingerprints carried from `0.9.0` remain unchanged.

## Why another RC is required

Stable `1.0.0` must not ship with two competing concrete-Mind creation models. New concrete Minds need one canonical path:

```text
exact immutable protocol release
→ deterministic neutral bootstrap
→ explicit subject + publication owner + Identity
→ exact release provenance in repository metadata and protocol lock
→ validated standalone concrete Mind
```

The correction is repository/bootstrap tooling rather than a new universal Identity, relationship, visual-identity, provider, or renderer concept. Publishing `rc.2` makes that corrected creation path immutable and testable before stable promotion.

## Conformance

The same required synthetic `person`, `organization`, `agent`, `project`, and `product` fixtures remain authoritative. Both required consumer modes must pass the existing deterministic probes for:

- Identity and subject binding;
- authored-vs-derived provenance;
- canonical visual resolution and integrity failure;
- unknown optional/required modules;
- frozen root-manifest behavior;
- deterministic neutral baseline;
- SemVer prerelease range evaluation.

The canonical bootstrap regression suite additionally proves exact release commit capture, tag/HEAD equality, floating-branch rejection, deterministic output, and schema-valid generated Minds.

## Concrete consumer synchronization

After formal `rc.2` publication, each real canary Mind should consume the exact immutable `v1.0.0-rc.2` release and update only protocol/release provenance required by the new candidate.

Canonical subject IDs, publication owners, Identity, authored relationships, provider-independent semantics, and concrete `mind.context_version` remain unchanged unless that concrete Mind independently changes durable authored content.

The current real-canary set is:

- `0x0sky/mind`;
- `aiaiaiai-org/mind`;
- `0xda-market/mind`;
- `nilx-one/mind`.

## Stable promotion boundary

Stable `1.0.0` may follow only after:

1. this candidate is formally published as an immutable GitHub prerelease;
2. the four real Minds validate against the exact `rc.2` release;
3. the independent `mind-web` consumer uses the corrected standalone bootstrap contract rather than the historical fork/copy creation model;
4. the complete create/load/auth/repair path is verified without introducing a second protocol authority;
5. no blocking universal protocol defect remains.

Any new universal semantic defect found after `rc.2` requires another RC. Stable promotion must not silently change the accepted final-RC contract.

## Publication boundary

This source file does not publish the candidate. Formal publication is a separate explicit `Publish Mind Protocol Release` workflow action from the verified `master` merge commit using the `prerelease` channel.

The immutable publication target, if approved, is `v1.0.0-rc.2`.
